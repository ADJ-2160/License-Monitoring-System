# License-Monitoring-System (CATIA DSLS License Monitoring & Analytics Dashboard)

이 시스템은 Dassault Systèmes License Server (DSLS) 기반 CATIA 라이선스의 실시간 동시 접속 모니터링, 일자별/시간대별 사용 통계 분석, 라이선스 거절(Denial) 추적 및 가상 증설 시뮬레이션을 제공하는 전용 시스템입니다.

---

## Harness 설계 철학: Dev-time vs. Run-time
본 템플릿 생태계는 개발 환경과 운영 환경을 엄격히 분리하는 철학을 기반으로 설계되었습니다.

1. **Dev-time(개발 시점) 집중 지원**
   - 이 템플릿은 코드를 작성하고 AI와 바이브코딩(Vibe Coding)을 진행하는 Dev-time 환경 제어에 100% 집중합니다.
2. **Run-time(운영 시점)의 책임 분리**
   - 사내망, 데이터베이스, Internal Tool, 사내 보안 인프라 등 실제 운영 환경(Run-time)은 보안상 이 템플릿에 직접 포함되지 않으며, 사용자가 직접 사내망 내에서 세팅하는 것이 바람직합니다.
3. **`conf/` 및 폴더 구조를 통한 런타임 보정**
   - Dev-time에 실제 사내 인프라를 연결할 수 없는 한계를 극복하기 위해, 엄격한 `conf/` 구조와 디렉토리 제약을 두었습니다. AI 에이전트는 이 정해진 구조와 설정 파일 형태를 믿고 코드를 작성하므로, 추후 Run-time에서 실제 사내 설정값만 채워 넣으면 코드가 완벽하게 동작하도록 보정해 줍니다.

## 목적
데이터 분석, 사내 간단한 웹 툴, 대시보드 등을 Python 기반(Streamlit 또는 FastAPI)으로 빠르고 유연하게 생성하기 위한 뼈대입니다. 불필요한 보일러플레이트를 제거하고 빈 도화지 상태로 제공하여 에이전트가 코드를 동적으로 작성하도록 유도합니다.

## 구조 및 Dev-time 하네스 세팅
이 템플릿은 런타임이 아닌 개발 시점(Dev-time)의 환경과 AI 에이전트 제어를 목적으로 구성되었습니다.

- `.agents/AGENTS.md`: AI 에이전트가 코드를 작성할 때 지켜야 할 핵심 지시서입니다. 템플릿 차원의 기본 규칙이 이미 정의되어 있습니다.
- `.devcontainer/`: Python 환경(Conda/Pip)이 세팅된 개발 샌드박스입니다. 에이전트가 패키지를 직접 설치하고 실행해 볼 수 있는 격리된 환경을 제공합니다.
- `app.py`: 에이전트가 코드를 작성할 단일 진입점입니다. (FastAPI 또는 Streamlit 코드가 작성됩니다)
- `requirements.txt`: 프로젝트 의존성 관리 파일입니다.

### `conf/` (환경 설정 영역 및 Run-time 브릿지)
데이터베이스 연동 정보나 외부 API 설정값 등을 중앙 집중화하는 폴더입니다.
- **런타임 하네스 바운더리(Boundary)**: 코드를 짜주는 AI(Code Agent)는 사내 DB나 내부망 서버에 직접 붙어서 테스트할 수 없습니다. 대신, 사용자가 `conf/db/`나 `conf/tools/` 하위에 연결 정보(스키마, API 엔드포인트)를 간단한 yaml 등으로 기재해 두면 됩니다.
- **활용 효과**: Code Agent는 이 설정 파일을 "Run-time에 접근 가능한 도구/데이터"라는 명시적인 경계선(Boundary)으로 인지합니다. 그 결과, 샌드박스에서 구동할 수 없는 사내 DB를 마치 연결된 것처럼 완벽하게 호출하는 Python 웹(FastAPI/Streamlit) 코드를 에러 없이 깎아냅니다.

## Vibe Coding 및 개인 커스텀 방법
사용자는 코드를 직접 작성하는 대신, 제공된 뼈대를 바탕으로 다음 과정을 통해 개발을 진행해야 합니다.

1. **AGENTS.md 다듬기**: 이미 배포된 `.agents/AGENTS.md`를 개인 프로젝트의 스코프와 목적에 맞게 수정하고 깎아나갑니다. (예: "디자인은 사내 테마를 따를 것", "특정 라이브러리 사용 금지" 등)
2. **Vibe Coding 요청**: 수정한 AGENTS.md를 기반으로 AI 에이전트에게 "이러한 기능을 하는 대시보드를 만들어라"라고 요청합니다.
3. **반복**: 에이전트가 코드를 작성하면, 결과를 확인하고 다시 AGENTS.md의 룰을 정교하게 깎아나가며 프로젝트를 완성합니다.

## 런타임 연동 (필수 작업)
이 템플릿은 Dev-time 하네스이므로 실제 사내 인프라에서 구동하기 위한 런타임 설정은 포함되어 있지 않습니다.
회사 인프라 내에서 정상적으로 동작하기 위해서는 개인 프로젝트 스코프별로 다음 항목들을 직접 연동해야 합니다.
- DB 연결 설정 및 마이그레이션
- 사내 API Key 및 인증(Authentication) 처리
- Internal Tool 및 MCP 연동 정보

## 에디터 및 CLI 연동 (Gemini CLI)
- VSCode와 `@google/gemini-cli`를 함께 사용하는 유저는 CLI 기반 동작을 위해 `.agents/AGENTS.md` 파일을 프로젝트 루트의 `./GEMINI.md`로 반영해두면 됩니다.
- 본 하네스와 AGENTS.md는 Gemini 모델에 최적화되어 있으므로, Claude나 Codex 등 타 모델과는 해석 방식이 맞지 않을 수 있습니다.
